# Глоссарий терминов

## Apply

Применение изменений, описанных в Terraform конфигурации. Выполняет создание, изменение или удаление ресурсов.

## Destroy

Удаление ресурсов, описанных в конфигурации, командой `terraform destroy`. Для ресурсов с операцией `suspend` по умолчанию **замораживает** инстанс (`suspend`), а не удаляет его — см. [«Как работает провайдер» §5](provider-behavior.md#5-delete-suspend) и термин `suspend` ниже.

## Import

Подключение уже существующего ресурса к Terraform state. Импорт не создает ресурс, а только добавляет его в состояние.

Короткий пример:

```bash
terraform import nubes_vc_vm_v3.my_vm <resource_id>
```

## Manifest (манифест)

Набор `.tf` файлов в одной папке, которые Terraform рассматривает как единую конфигурацию.

## Module

Переиспользуемая часть конфигурации Terraform. Может использоваться для шаблонов и типовых наборов ресурсов.

## Plan

Просмотр изменений, которые Terraform собирается применить. Выполняется командой `terraform plan`.

## Resource

Описание управляемого объекта в Terraform. Например, виртуальная машина или сеть.

## Stack (стек)

Отдельный набор ресурсов Terraform, управляемый собственным `terraform state`. Обычно это отдельная папка с `.tf` файлами.

## State

Файл состояния Terraform, в котором хранится информация о созданных ресурсах и их текущих параметрах.

Удаление ресурса только из state (без удаления в облаке):

```bash
terraform state rm nubes_vc_vm_v3.my_vm
```

## Workspace

Логическое разделение одного и того же набора конфигураций по разным окружениям. Имеет отдельные state.

# Термины Nubes

## adopt (усыновление)

Режим, при котором `apply` не создаёт новый объект, а берёт под управление уже существующий инстанс с тем же именем. Включается флагом `adopt_existing_on_create = true`. Аналог `terraform import`, но срабатывает в обычном `apply`. Если найден остановленный инстанс (`suspend`) и параметры совпадают — выполняется `resume`.

## suspend (усыпление) и resume (пробуждение)

Операции остановки и запуска инстанса без его удаления. При усыплении ресурсы высвобождаются, инстанс сохраняется и возвращается тем же `resume` (тот же `id`). Поведение при `terraform destroy` задаётся флагом `suspend_on_destroy` (по умолчанию `true` — усыпление, а не удаление).

## realm (resource_realm)

Платформа, на которой разворачивается объект. Для кластерных сервисов это Kubernetes-кластер (например, `k8s-4-ext-nubes-ru`), для S3 — сам S3-кластер (`s3.msk-1.ngcloud.ru`), для LLM — `llmAi.aillm.ru`. Обычно указывается в блоке `startup_configuration`.

## ip_space

Пул внешних IP-адресов, выделенный на организации. Используется для публикации внешнего адреса ресурса (например, `internet-no-antiddos-v1`). Значение `no-needed` означает, что внешний адрес не требуется.

## ref-параметр (ссылка на сервис)

Поле, которое связывает один ресурс с другим (`s3_uid`, `vdc_uid`, `nsxt_uid`, `psql_uid`, `vapp_uid` и т.п.). Принимает UUID или имя связанного инстанса; имя провайдер резолвит в UUID. Значение обычно берётся из выхода родительского ресурса — например, `nubes_s3.storage.id`.

## keep_on_destroy и suspend_on_destroy

Флаги, задающие поведение `terraform destroy`:

- `suspend_on_destroy = true` (по умолчанию) — инстанс переводится в `suspend`, а не удаляется.
- `keep_on_destroy = true` — в облаке ничего не меняется, ресурс убирается только из state (приоритетнее `suspend`).

## «not created»

Статус инстанса после неудачной операции создания. Такой инстанс блокирует имя и не удаляется через API — его нужно удалить вручную в Личном кабинете, после чего повторить `apply`.

## Vault

Хранилище секретов платформы. Пароли и ключи, которые генерирует платформа, доступны в выходе ресурса `vault_secrets` (тип map, `sensitive`); список доступных ключей — в `vault_fields`.
